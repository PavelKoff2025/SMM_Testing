# deploy-smm-testing — развёртывание проекта SMM_testing

Этот skill ведёт коллегу через полное развёртывание проекта SMM_testing — системы
автоматизированного тестирования студентов (итоговый проект курса «Вайбкодинг.
Профессия», Claude Code). Цель: получить идентичную локальную копию и/или живое
демо на Render free.

Репо: **https://github.com/PavelKoff2025/SMM_Testing**
Живое демо автора: **https://smm-testing.onrender.com**

## Как вести коллегу

- Развёртывание = внешнее действие. **Перед деплоем на Render** подтверди у
  пользователя, что он готов создать облачный сервис (понадобится аккаунт Render и
  fork репо на свой GitHub). Локальный запуск можно делать без подтверждений.
- Не додумывай значения секретов. Если коллега не дал `OPENAI_API_KEY`,
  `TEACHER_PASSWORD` и т.п. — предложи демо-режим (`AI_MOCK=1`, `APP_ENV=dev`,
  `SMTP_ENABLED=0`), где ничего из этого не нужно.
- После каждого шага проверяй результат (команда `python -c`, `curl`, открытие
  `http://127.0.0.1:8000`) и только потом двигай дальше.
- Пиши на русском, кратко, с пояснением «почему».
- Команды давай под macOS/zsh (основная среда автора). Если у коллеги Linux/Windows —
  адаптируй активацию venv (`venv\Scripts\activate` на Windows).

## Стек (коротко, чтобы отвечать на вопросы)

- **Backend:** Python + FastAPI (uvicorn как ASGI-сервер).
- **БД:** SQLite + SQLAlchemy ORM (файл `data/smm_testing.db`, без отдельного
  сервера).
- **Фронт:** Jinja2 + HTML/CSS, серверный рендер (без SPA-сборки).
- **Генерация тестов:** OpenAI SDK + GPT-4o-mini из текста PDF-презентации
  (pdfplumber). Есть мок-режим `AI_MOCK=1` — демо-вопросы без вызова OpenAI.
- **Расписание тестов:** APScheduler. **Email-отправка:** smtplib (Яндекс SMTP),
  выключается флагом `SMTP_ENABLED=0`.
- **Деплой:** Render free, Blueprint `render.yaml`.

## Пререквизиты

Перед стартом проверь и озвучь, что нужно:

1. **Python 3.11+** — `python3 --version`. Версия важна: проект использует
   `fastapi==0.141.1`, которая тащит совместимую `starlette==1.6.0`. На старом
   системном Python со `starlette<1.0` шаблоны падают с 500.
2. **git** — `git --version`.
3. **OpenAI API-ключ** — *опционально*. Нужен только для реальной генерации
   тестов из PDF (`AI_MOCK=0`). Для демо/знакомства не требуется (`AI_MOCK=1`).
4. **Аккаунт Render** (и fork на свой GitHub) — *опционально*, только для
   облачного деплоя.
5. **Пароль приложения Яндекс** — *опционально*, только для отправки результатов
   студентам по SMTP (`SMTP_ENABLED=1`). По умолчанию выключено.

Если чего-то нет — скажи, можно ли работать без этого (для локального демо
достаточно только Python и git).

## Этап 1. Клонирование репо

```bash
git clone https://github.com/PavelKoff2025/SMM_Testing.git
cd SMM_Testing
```

Проверь, что на месте: `README.md`, `requirements.txt`, `.env.example`,
`config.py`, `app/`, `render.yaml`.

## Этап 2. Виртуальное окружение и зависимости

**Обязательно в venv** — это не рекомендация, а требование. В `requirements.txt`
есть комментарий: транзитивная `starlette` из системного Python может оказаться
старой (<1.0), и тогда все шаблоны упадут с 500. Запускать только так:

```bash
python3 -m venv venv
source venv/bin/activate            # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

Проверь версию starlette после установки:

```bash
venv/bin/python -c "import starlette; print(starlette.__version__)"
```

Ожидается `1.6.0` (ставится автоматически с `fastapi==0.141.1`). Если видно
`0.x` — значит, установка пошла не в venv; пересоздай окружение и активируй его.

## Этап 3. Переменные окружения (.env)

```bash
cp .env.example .env
```

Затем помоги коллеге заполнить `.env` под его сценарий. **Минимальный демо-набор**
(ничего секретного не нужно, всё уже дефолты в `.env.example`):

| Переменная | Демо | Реальный запуск |
|---|---|---|
| `APP_ENV` | `dev` | `prod` (старт упадёт на дефолтных секретах — это защита) |
| `AI_MOCK` | `1` | `0` (нужен `OPENAI_API_KEY`) |
| `OPENAI_API_KEY` | не нужен | `sk-...` реальный ключ |
| `TEACHER_PASSWORD` | `changeme` (только демо) | свой пароль, не `changeme` |
| `SECRET_KEY` | `dev-secret-change-me` | сгенерить: `python -c "import secrets; print(secrets.token_urlsafe(48))"` |
| `SMTP_ENABLED` | `0` | `1` (нужен `SMTP_PASSWORD` — пароль приложения Яндекс) |
| `DEMO_AUTOSEED` | `0` локально | `1` только на Render free (эфемерный диск) |

Поясни коллеге:
- `APP_ENV=prod` намеренно падает, если `TEACHER_PASSWORD` или `SECRET_KEY`
  равны дефолтам — это `config.ensure_prod_secrets()`, чтобы боевой сервис не
  уехал с публично известными секретами. См. `config.py`.
- `DEMO_AUTOSEED=1` локально **не нужен** — он затрёт локальную БД демо-данными.
  Его включает только Render (см. `render.yaml`), где диск эфемерный и БД всё
  равно пустая при каждом старте.

## Этап 4. Локальный запуск

```bash
venv/bin/python -m uvicorn app.main:app --reload --port 8000
```

Стандарт из README — `uvicorn app.main:app --reload`. Но запуск через
`venv/bin/python` гарантирует, что берётся Python именно из venv (см. грабли со
starlette). `--reload` удобен для разработки.

Проверка:
1. Главная: **http://127.0.0.1:8000** — должна открыться страница сервиса.
2. Документация API: **http://127.0.0.1:8000/docs** — автогенерация FastAPI.
3. Кабинет преподавателя: **http://127.0.0.1:8000/teacher** — войти под
   `TEACHER_PASSWORD` из `.env` (в демо — `changeme`).

Если в демо-режиме (`AI_MOCK=1`) коллега хочет посмотреть генерацию теста: в
кабинете преподавателя загрузи любой PDF-презентации → вернётся демо-набор
вопросов 4/4/2 без обращения к OpenAI.

Если всё открылось — локальное развёртывание готово. Деплой на Render — следующий
раздел, по желанию.

## Этап 5. Деплой на Render free (опционально)

Render free даёт живое демо, но с ограничениями: **эфемерный диск** (SQLite
обнуляется при каждом деплое/перезапуске), один воркер, холодный старт через
~1 мин. Для демо комиссии этого достаточно; боевой продакшен — отдельная задача
(не раньше февраля 2027, см. README).

Перед деплоем **подтверди у пользователя**, что он готов:
- сделать fork репо `PavelKoff2025/SMM_Testing` на свой GitHub;
- залогиниться на https://render.com и подключить свой GitHub.

### Шаги деплоя

1. **Fork** репо `https://github.com/PavelKoff2025/SMM_Testing` на GitHub
   коллеги (кнопка Fork). Свой fork потом подключается к Render.
2. В Render: **New → Blueprint**, выбрать свой fork репо. Render сам прочитает
   `render.yaml` из корня — там уже описан сервис `smm-testing` (free, frankfurt,
   `uvicorn app.main:app --host 0.0.0.0 --port $PORT`).
3. Переменные окружения из `render.yaml` подставятся автоматически, кроме двух:
   - `SECRET_KEY` — `generateValue: true`, Render сгенерит сам.
   - `TEACHER_PASSWORD` — `sync: false`, **ввести вручную** в dashboard Render.
     Для демо можно `demo`; сообщить комиссии отдельно.
4. Подтвердить создание. Render поставит зависимости и стартует сервис. URL
   будет вида `https://smm-testing-<suffix>.onrender.com`.
5. **Проверка:** открыть URL. Учитывая холодный старт, открыть за 1–2 мин до
   показа и дождаться загрузки главной. На пустой БД сработает
   `DEMO_AUTOSEED=1` (см. `app/seed.py: seed_demo_for_deploy`) — поднимется
   демо-тест лекции 1 и два студента с попытками, чтобы сразу видеть живой
   сервис.
6. Войти в кабинет преподавателя под `TEACHER_PASSWORD`, заданным в п.3.

### Что точно НЕ хранить в репо

`OPENAI_API_KEY`, `SMTP_PASSWORD`, `TEACHER_PASSWORD`, `SECRET_KEY` — только в
`.env` (локально) или в dashboard Render (облачно). В `.gitignore` репо уже
исключён `.env`. Не коммитить секреты ни при каких условиях.

## Грабли и частые проблемы

- **500 на всех шаблонах после запуска** — почти всегда `starlette<1.0`.
  Причина: запуск не из venv, либо pip поставил в системный Python. Лечится
  запуском строго через `venv/bin/python -m uvicorn ...`.
- **Старт падает с «небезопасные секреты»** — это `APP_ENV=prod` при дефолтных
  `TEACHER_PASSWORD`/`SECRET_KEY`. Для демо поставь `APP_ENV=dev`; для прода —
  задай свои значения и сгенерируй `SECRET_KEY`.
- **Демо на Render не загрузилось / 404** — холодный старт free-тарифа. Не баг:
  открой URL за 1–2 мин до показа, дождись загрузки главной. При первом
  обращении сервис просыпается.
- **Генерация теста из PDF не идёт** — проверь `AI_MOCK`: `1` = мок без OpenAI
  (ключ не нужен), `0` = реальный вызов GPT-4o-mini (нужен `OPENAI_API_KEY`).
- **Email-уведомления не приходят** — по умолчанию `SMTP_ENABLED=0`, письма не
  отправляются (результат виден в кабинете студента). Для отправки: `SMTP_ENABLED=1`
  + `SMTP_USER`/`SMTP_PASSWORD` (пароль приложения Яндекс, не основной пароль).
- **БД на Render обнулилась** — эфемерный диск free-тарифа. Это ожидаемо; для
  боевого запуска нужен VPS с постоянным диском (в README — roadmap на февраль
  2027).

## Адаптация под другой курс

Сервис курсо-независимый. Чтобы запустить тестирование по другому курсу,
коллеге достаточно (без правки логики):

- загрузить свои PDF-презентации или JSON-тесты в кабинете преподавателя;
- поменять в `config.py`: `ADMISSION_TESTS_REQUIRED`, `ADMISSION_CORRECT_REQUIRED`,
  `PASS_THRESHOLD`, `STUDENT_EMAIL_DOMAIN`;
- указать свои SMTP-реквизиты в `.env`.

Подробно — раздел «Развитие сервиса» в `README.md`.
